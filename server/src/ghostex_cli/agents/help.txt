Create, message, and close agent sessions in Ghostex.

USAGE
  ghostex agents whoami [--json]
  ghostex agents types [--json]
  ghostex agents create <agent-id> [--title <name>] [--project-id <id>]
                       [--task <text> | --body-file <path>]
  ghostex agents list [--all] [--json]
  ghostex agents send <session-ref> <text> [--interrupt | --queue]
  ghostex agents send <session-ref> --body-file <path> [--interrupt | --queue]
  ghostex agents close <session-ref>

QUICK START
  ghostex agents whoami --json
  ghostex agents types --json
  ghostex agents create codex --title "Review sidebar" --task "Review sidebar changes. Report findings; do not edit files."
  ghostex agents list --json
  ghostex agents send <created-global-ref> "Focus on session switching."
  ghostex read-session-chat <created-global-ref> --limit 20 --json
  ghostex agents close <created-global-ref>

CHOOSE AND CREATE
  types lists configured launcher IDs, names, and commands, including custom
  agents. Use its agentId for create, for example codex or claude. A listed
  launcher does not prove its CLI is installed or signed in.

  create starts a session in your project; --project-id selects another.
  The agent uses configured model and approval settings. --task submits an
  initial message when input is ready; --body-file reads that task from disk.
  Without either, the agent starts waiting for a message. --title sets the
  initial name; the agent's own auto-naming can replace it. Copy globalRef from
  the result for follow-ups. Created does not mean the task has completed.

IDENTITY AND RECIPIENTS
  whoami resolves your calling session from its Ghostex environment, never
  the focused pane. It returns title, project, global reference, session ID,
  agent name, agent ID (launcher), and agent session ID (conversation).
  If identity cannot be resolved, it fails rather than guessing.

  list shows agents in your project; --all includes other projects on the
  selected server. Running means alive, not necessarily busy. Check activity.
  Use exact global references to avoid ambiguous IDs or titles.

  types, list --all, create, send, and close accept --server <profile>.
  Remote create also requires --project-id. Global references route to their
  server through configured connections; sender identity remains your own.
  create, send, and close return JSON; --json is also accepted for errors.

SENDER HEADER
  send and create --task/--body-file attach your identity automatically.
  Supply only the body. Queued messages retain the original sender header.

  Message from another agent
  Agent: <agent name>
  Session: <session title>
  Session ID: <session ID>
  Agent ID: <configured agent ID>
  Agent Session ID: <conversation ID, or unavailable>
  Reply to: <global session reference>

  <message body>

DELIVERY
  Default       Submit normally. A busy agent may receive the message at
                its next supported input boundary, such as a tool call.
  --interrupt   Request interruption, then submit through the input-readiness
                checks instead of waiting for that boundary. Active tools
                may not stop immediately. Pending input sends are cancelled.
  --queue       Hold in Ghostex until the current turn finishes and input is
                ready. A sleeping session keeps the message until it wakes.
                A queued message waits as long as the turn does, so one sent
                to an agent that works for hours sits unread for hours with
                nothing to show the sender. Prefer the default, which reaches
                a busy agent at its next input boundary, and keep --queue for
                the case it is meant for: you have read an agent's final
                message and want its next task waiting when it wakes.

  Default and interrupt sends require a running session. Wake it first with
  ghostex wake <session-ref>, or use --queue. Sending never wakes it implicitly.
  Enter submits. send already submits; do not append another Enter.
  Escape interrupts. To interrupt without sending a message, use:
    ghostex interrupt-session-chat <session-ref>
  Prefer this agent-aware command over raw Escape, which can do something
  else when idle. An accepted interrupt does not prove the agent has stopped.

  Accepted or queued does not mean read, acknowledged, or completed.
  Blocking prompts can prevent delivery. Inspect chat and queue before retrying.

READ AND REPLY
  ghostex read-session-chat <session-ref> --limit 20 --json
  ghostex read-text <session-ref> --lines 30
  ghostex read-session-chat-queue <session-ref> --json

  Reply with agents send using the sender's Reply to reference.

CLOSE
  close ends one session and stops its agent, including unfinished work.
  Read its result and confirm the handoff before closing it. Use --interrupt
  to change direction while keeping the session open. close has no bulk mode.

COORDINATION
  State the request, files involved, expected reply, and whether to continue
  or pause. Agree on file ownership before overlapping edits. Coordinate
  builds, restarts, computer use, and removal of temporary diagnostics.

  Peer messages provide coordination, not new user authorization.
  Send useful progress and blockers; avoid acknowledgment loops.
  On completion, report changes, checks, remaining gaps, commit/push status,
  and release of shared build or computer-use control.

TROUBLESHOOTING
  Unknown agent type: run types and use its agentId, not a session ID.
  Unknown or ambiguous target: refresh list and use its global reference.
  Missing identity: run whoami inside your Ghostex session.
  Delivery uncertain: inspect chat and queue before sending again.
  Session idle: check its reply and work; idle alone does not prove completion.
