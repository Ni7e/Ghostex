## Workspace Layout Model

- The workspace is modeled as a tree of tabs, splits, and leaf panes.
  - Split direction can be horizontal or vertical.
  - Split ratios are user-resizable and persisted.
  - Tab groups preserve tab order, active tab, and pane ownership.
- Multiple sessions without an explicit split should appear as tabs, not auto-created split panes.
- Explicit split actions create split panes.
  - Normal new terminal/browser actions add a tab in the clicked or focused pane.
  - Full-width secondary terminal creation appends a bottom row rather than replacing the current tree.
- Split handles are real layout regions.
  - The visible divider is also the grab target.
  - Visual separators are non-interactive.
  - Double-clicking a split handle resets the split ratio.
- Single-pane layouts still show the native tab bar.

## Native Tabs Bar

- Tabs are native workspace chrome because terminal and CEF-backed surfaces sit above React.
- Every pane has a tab/title bar, including single-pane layouts.
- Tab strip behavior:
  - Workspace tabs use wider tab sizing.
  - Command-pane tabs are more compact.
  - Overflow scrolls horizontally.
  - The active clipped tab gets a sticky edge affordance to reveal it.
- Tab visuals:
  - Selected sleeping tabs still look selected.
  - Inactive sleeping tabs are subdued.
  - Pane focus should not visually dim or brighten the tab bar.
  - Activity and status dots show command, agent, browser, attention, or delayed-send state.
- Tab actions:
  - Inline close appears where allowed.
  - Context menus are scoped to the tab's pane group.
  - Far-right overflow is for pane/layout actions, not per-tab commands.
  - Double-clicking a workspace tab enters or reverses Focus mode.

## Sleeping, Mounting, And Popped-Out Sessions

- Sleeping sessions stay in the persisted tab/split layout.
  - They are removed from active mounted surfaces.
  - Their tab remains visible.
  - Their pane body becomes a placeholder.
- Click-to-wake is the default behavior.
  - Selecting a sleeping tab makes that placeholder active.
  - It does not immediately wake the runtime unless the wake affordance or body is activated.
  - Current GPUI source/runtime evidence moves an explicitly activated placeholder body/card to `Mounting`; sleeping wake and popped-out reattach stay out of the startup pipeline and may reattach only an exact runtime parked owner for the same durable shell session and process-local runtime id with current visible body geometry. Restored-unmounted materialization may enter the existing startup pipeline. This is accepted for the source-ledger purpose, but no validation commands were run.
- Mounting sessions appear as startup placeholders until ready.
  - New terminal, explicit restored-unmounted materialization, and in-process failed-startup retry `Mounting` states remain startup eligible; explicit failed-startup retry rotates the process-local runtime attempt id before retry startup sync/intent, while restored materialization keeps the current process-local runtime id. Sleeping/popped-out activation and restored shell-state `mounting` are Mounting-only unless an exact parked owner and current geometry can be moved; post-restart materialization remains presentation-only until a separate contract exists.
- Restored or unmounted tabs remain real layout participants.
  - They can be selected.
  - They can be dragged.
  - They should wake or materialize through the normal explicit activation or drop flow; tab selection alone remains presentation-only.
- Popped-out panes remain represented in the workspace tree.
  - The in-app slot shows a placeholder or reattach state.
  - Current GPUI source evidence moves explicit body/card activation to `Mounting` as reattach-pending, prevents it from entering the new-startup candidate path, and can move only an exact parked runtime owner once; that no-duplicate parked-owner/reattach contract is accepted source-ledger evidence for this pass. Running/app proof remains user-side outside the current no-validation workflow and is not a source-ledger blocker.

## Drag, Drop, Reorder

- Dragging starts from tabs after a small movement threshold.
- Dropping in the same tab strip reorders within that tab group only.
- Dropping onto a pane body:
  - Center drop groups as tabs.
  - Edge drop splits beside the target.
  - Workspace supports left, right, top, and bottom edge splits.
- Dragging an active tab to its own edge can split that tab out of a multi-tab pane.
- Dragging a sleeping, restored, or unmounted tab should preserve or restore the session instead of losing it.
- Browser and CEF surfaces are hidden during native tab drag to avoid flicker.
- Drag feedback should clearly distinguish tab grouping from edge splitting.

## Command Pane

- The command pane is a separate bottom workspace surface, not part of normal workspace tabs.
- It has its own tab/split layout and active session state.
- Modes:
  - Pinned mode reserves height and pushes the workspace up.
  - Floating mode floats above the workspace while keeping a collapsed bottom strip.
  - Collapsed mode shows only the compact bottom command strip when command sessions exist.
- Height behavior:
  - Expanded height is clamped between a small and large workspace fraction.
  - Dragging the top rail resizes it.
  - Double-clicking the rail resets to the default height.
- Command tab behavior:
  - New command terminals are added to the clicked or focused command pane.
  - Command pane supports tab grouping and left/right horizontal splits.
  - It does not support top/bottom command splits.
  - Closing the last command terminal collapses the panel.
- Focus behavior:
  - F12 opens and focuses the command pane, or collapses it when already focused.
  - Hiding the command pane returns focus to the previous workspace terminal or browser where possible.
  - Command terminals are separate from workspace terminals and should not be merged by Merge All Tabs.

## Focus, Close, And Keyboard Behavior

- Directional focus moves through the rendered native layout.
  - It can move between workspace panes and the expanded command pane.
  - It must respect sleeping placeholders instead of skipping or replacing them incorrectly.
- Tab cycling operates within the focused split-pane tab bar.
  - Forward and reverse cycling include sleeping and unmounted tabs.
- Close behavior is surface-aware.
  - In a command pane, close closes the focused command terminal.
  - In project-editor modes, close should not close the project editor itself.
  - It may close the visible companion terminal when that side pane owns focus.
- Closing an active workspace tab selects the neighboring tab in the same pane when possible.
  - Closing the final tab in a split branch collapses that branch.
- Focus mode is a reversible zoom of a pane or tab group.
  - Sleeping-only split panes should not count as visible panes for Focus availability.

## Browser, Kanban, And Manage Views

- Source, Browser, Kanban, and Manage are project-editor workspace modes.
  - They replace the main workspace area while active.
  - Normal terminal/browser split surfaces are hidden while the project editor is active.
  - The command pane can still appear at the bottom.
- These views can have an optional left companion pane.
  - The companion is usually a terminal or browser side pane.
  - Width is resizable and persisted.
  - Double-clicking the companion divider resets width.
- Browser view:
  - Uses native AppKit tabs above the browser toolbar.
  - Each browser tab owns its own CEF view so page state survives tab switches.
  - Inactive restored browser tabs can remain sleeping until selected.
  - Closing the last loaded browser tab leaves an address-only new-tab placeholder.
  - First open should use the project's GitHub remote when available, otherwise the default web start page.
- Kanban view:
  - The macOS app uses a first-party bundled web page for the project board; GPUI must mount the equivalent project board through CEF for cross-platform parity.
  - It is project-scoped and disabled without a project.
- Manage view:
  - The macOS app uses a first-party bundled file/workarea page; GPUI must mount the equivalent Manage page through CEF, with a separate file-bridge contract.
  - It is gated behind Debugging Mode plus beta features.
  - It is project-scoped and disabled without a project.
- Project-editor surfaces have auto-sleep behavior.
  - Source, Browser, Kanban, and Manage have independent sleep timers.
  - Recently used surfaces stay awake up to the configured cap.

## Layout Ownership Rules

- Native workspace, command pane, browser, Kanban, Manage, terminal, and divider regions should be laid out as non-overlapping regions.
- Interactive boundaries should be real views or regions, not transparent overlays.
- Visual-only chrome should not compete for input.
- Project editor, companion pane, and command pane should preserve surface identity instead of recreating views during ordinary layout changes.
