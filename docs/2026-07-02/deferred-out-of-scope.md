## Deferred from Batch 1

- [1.2] **Remote-session Full reload / Close After Done parity edges** — GPUI `fullReloadSession`/`restartSession` handle local sessions only (macOS also reloads remote presentation sessions via `reloadRemotePresentationSession`). Close After Done timers do track remote rows, but firing closes via the standard remote `killSession` path without the macOS local lifecycle pre-patch. Re-entry: `gpui/sidebar/gxserver-runtime.ts` `fullReloadSession` / `completeCloseAfterDoneTimer`.
- [1.2] **sleepInactiveProjectSessions delayed-send exclusion** — macOS additionally excludes sessions with an active Delayed Send from bulk sleep; GPUI's runtime does not have an Agents-session delayed-send projection to check yet (command panes track it in Rust). Re-entry: `collectInactiveProjectSessionIds` once a delayed-send projection exists.
- [1.4] **Search-by-Text atuin/history prefix** — macOS launches `gx f` with `withAtuinIgnoredShellHistoryPrefix` so it stays out of shell history; GPUI launches it as an agent-session launch command without the prefix. Cosmetic difference.
- [1.5] **Named groups for remote-machine projects** — the new client-side group model covers local projects only; remote-machine project sections do not offer New Group. Re-entry: extend `workspace-session-groups.ts` ids to carry a machine scope.
- [1.5] **Group model is GPUI-local, not the shared macOS module** — GPUI persists a session-id→group overlay (`gpui/sidebar/workspace-session-groups.ts`) rather than adopting `shared/simple-grouped-session-workspace-state.ts` wholesale, because GPUI's sidebar derives groups from gxserver presentation snapshots instead of owning a full client-side session-grid workspace. Semantics (ids `group-${n}`, max 20, create-from-session, order sync) match. Note: shipped macOS currently exposes NO group-creation UI (the handlers exist but nothing posts `createGroup`); GPUI now exposes "New Group" / "Move to New Group" gated on the new `canCreateSessionGroup` contract flag, so macOS rendering is unchanged.

## Deferred from Batch 3

- [3.1] **First-prompt Enter-submit skips background tabs** — GPUI can press Return only on the mounted active tab of a pane; if the user switches tabs while the title is generating, the staged `/rename` stays unsubmitted in the prompt (macOS sends Enter to hidden views). Re-entry: `send_enter_key_to_local_agents_workspace_session` (main.rs) once background-tab key delivery exists.
- [3.1] **No terminal-input-suppression "Generating title" overlay** — macOS Swift draws a blocking pane overlay and suppresses typing during generation; GPUI only holds the sidebar card spinner until after the Enter submits. Re-entry: Agents terminal body chrome (same normal-layout row discipline as the search bar).
- [3.5] **No prompt-editor prewarm** — macOS prewarms a hidden Monaco child window after launch (`prewarmFloatingPromptEditorIfNeeded`); GPUI cold-opens, so the first Ctrl+G pays CEF+Monaco startup. Re-entry: prewarm the reusable app-modal host with the prewarm open message contract already present in `modal-host.tsx`.
- [3.5] **Editor window frame is fixed 432×352** — macOS persists a draggable/resizable native frame (`floatingPromptEditor.frame.v1` defaults key) and passes `initialFrame` to React; GPUI opens a fixed-size centered window, and React's in-page move/resize moves the panel inside the window instead of moving the window. Re-entry: GPUI window-frame persistence + `initialFrame` in the open message.
- [3.5] **Native red-X close of the editor window skips the status handshake** — no GPUI app-modal window has a native-close observer (pre-existing gap for all modals); a red-X close leaves the CLI polling until Save/Cancel/replacement or app quit (socket close ⇒ CLI resolves saved). Save/Cancel/Ctrl+G/Escape are the supported paths. Re-entry: window-close observation on the app-modal handle + `saveActiveFloatingPromptEditorForAppLifecycleClose` parity on quit.
- [3.5] **Closing the originating terminal does not close-and-save the editor** — macOS sends `floatingPromptEditorCloseAndSave` when the launching terminal closes. Re-entry: the local workspace close path in main.rs.
- [3.6] **TIFF/HEIC/PNM previews (and clipboard TIFF bitmaps) are not re-encoded** — macOS re-encodes everything to PNG via NSImage; GPUI has no native image decoder, so previews are limited to Chromium-renderable formats (png/jpg/gif/webp/svg/bmp/ico/avif, 10MB cap) and a TIFF bitmap paste stores `.tif` without a thumbnail. Re-entry: add an image decode dependency or a CoreGraphics FFI re-encode.
- [3.4] **58743 port contention between the two apps** — whichever Ghostex app binds first owns the CLI bridge and the token file (last writer wins); the second app shows a warning toast and runs bridge-less, so Ctrl+G in its terminals uses the machine editor. Same single-owner contract as macOS; matters for side-by-side parity testing.

## Deferred from Batch 5

- [5.2] **Open-target manual re-scan has no trigger (parity)** — the macOS host protocol declares `refreshWorkspaceOpenTargetAvailabilityFromTitlebar` but nothing in shipped macOS sends it (titlebar Open In dropdown = target rows + Configure only), so the live macOS behavior is the startup scan alone. GPUI ports exactly that: `start_gpui_workspace_open_target_availability_scan` at launch. Re-entry: a "Refresh Targets" row in `show_gpui_open_targets_menu` (main.rs) re-running the scan with force-persist semantics if a manual recheck is ever wanted.
- [5.6] **git-editor auto-sleep family stays out of scope** — `autoSleepGitEditor*` settings keys exist and macOS enforces them (`native-sidebar.tsx` ~:43004), but GPUI has no git-editor surface at all; the whole family is tied to Decision #6 (Group 10 git-editor + automate surfaces). Re-entry: lands with the git-editor surface decision; wire a GitEditor variant into the Rust `TitlebarMode` auto-sleep mapping (main.rs ~:67333) plus the duration keys in shared_settings.rs.
- [5.6] **Require-resume exclusion checks daemon-published fields, not per-agent catalog validation** — GPUI's `autoSleepRequireAgentResumeCommand` gate (new in Batch 5) excludes sessions with no `agentSessionId`/`agentSessionPath`/`trustedResumeTitle` in the gxserver presentation. macOS additionally validates per-agent reference formats and that the agents catalog has a launch command (`canRestoreNativeTerminalSession`, native-sidebar.tsx:22554). The daemon normalizes those fields before publishing, so the practical delta is small; a session with a stale-but-present reference could still auto-sleep on GPUI where macOS would keep it awake. Re-entry: expose a daemon-computed `canResumeWithAgent` on the presentation session (gxserver-rs presentation.rs) and gate on that instead.
- [5.4] **Ghostty terminal settings: no live reload; config loads at Ghostty-app-owner creation only** — code-verified 2026-07-02. Saves DO write the managed Ghostty config file (`sync_gpui_ghostty_config_file_after_settings_save` → the same `~/Library/Application Support/{com.mitchellh.ghostty,com.ghostty.org,Ghostty}/config[.ghostty]` candidates macOS writes), and `font-size` reaches every new surface immediately via the per-surface config request maps refreshed in the post-save fan-out. But theme/font-family and the other config-backed keys are read only by `ghostty_config_load_default_files` at `GhosttyAppOwner` creation, and GPUI's two app owners (`agents_terminal_ghostty_app`, `command_terminal_ghostty_app` in main.rs) are created lazily once per app run and never recreated — so those edits reach terminals at relaunch (or the family's first-ever terminal in the current run if none existed yet). Running surfaces never reload: the GPUI GhosttyKit FFI has no `ghostty_app_update_config` binding. macOS by contrast live-reloads all surfaces on a 3s debounce (`scheduleGhosttyConfigReload` → `Ghostty.reloadConfig()` → `ghostty_app_update_config`, AppDelegate.swift:5486 / TerminalWorkspaceView.swift:1785). Re-entry: bind `ghostty_app_update_config` in `ghostty_kit.rs`, keep a `GhosttyConfigOwner` reload path, and call it from the fan-out with the same debounce semantics. Do not fake it by dropping/recreating surfaces.
